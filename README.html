uvm_base —— 通用 UVM 母版库（与具体协议无关）

本库不含任何 DUT，通过 example/ 自证与协议无关。

0.4 已知环境坑与处理（换机器 / 重装 VCS 后需重做）

① GCC ≥ 12 编译 UVM DPI 失败

uvm_hdl_vcs.c:34: error: extended character “ is not valid in an identifier

UVM 1.2 的 DPI 源文件里 #error 用了弯引号（该分支实际不会编译，但会被扫描）。处理（二选一）：

# A. 用 VCS 支持的编译器
sudo apt-get install gcc-4.8 g++-4.8 && make check VCS_CXX=g++-4.8

# B. 改工具文件（本机已执行，原文件备份为 *.orig_bak）
V=$VCS_HOME/etc/uvm-1.2
sudo perl -CSD -pi -e 's/\x{201C}/"/g; s/\x{201D}/"/g; s/\x{2019}/'"'"'/g' \
    $V/dpi/uvm_hdl_vcs.c $V/src/dpi/uvm_hdl_vcs.c

② glibc ≥ 2.34 链接失败

undefined reference to `pthread_yield'

glibc 2.34 起删除 pthread_yield()。本仓库脚本已自动处理：检测到 glibc ≥ 2.34 时生成 .vcs_compat/pthread_yield_stub.o（内容为 int pthread_yield(void){return sched_yield();}） 并通过 -LDFLAGS 注入链接，无需手工干预。

③ Verdi 路径层级

VERDI_HOME 必须指到带版本号那一层（.../verdi/Verdi_O-2018.09-SP2），否则 FSDB PLI 找不到，脚本会自动退回 VCD。

2. 依赖关系（三层）

uvm_pkg        (Synopsys 自带 UVM 1.2，不修改)
     ↑ import
uvm_base_pkg   (本仓库：通用样板层)
     ↑ import
项目 pkg        (如 dvp_pkg：协议相关)
层提供什么
uvm_pkgphase / factory / config_db / TLM / sequencer / report 机制
uvm_base_pkg每个项目都要重复写的样板：骨架类、配置基类、比对基类、test 流程、plusarg、脚本
项目包interface、事务字段、驱动时序、比对规则、用例

3. 类层次与项目继承关系

uvm_base_cfg          <-- 项目 cfg       (dvp_agent_cfg / dvp_env_cfg)
uvm_base_item         <-- 项目 item      (dvp_frame_item / dvp_rx_line_item ...)
uvm_base_sequencer#REQ<-- 项目 sequencer
uvm_base_driver  #REQ <-- 项目 driver    只实现 pre_run() / do_drive_item()
uvm_base_monitor #TR  <-- 项目 monitor   只实现 pre_run() / do_monitor()
uvm_base_agent   #CFG <-- 项目 agent
uvm_base_scoreboard#CFG<-- 项目 scoreboard / checker
uvm_base_seq     #REQ <-- 项目 sequence  只实现 new_item()
uvm_base_env     #CFG <-- 项目 env
uvm_base_test         <-- 项目 test      只实现 create_main_sequence() / main_sequencer()

4. 搭一个新项目的步骤

  1. 建 filelist.f，首行放 +incdir+<uvm_base>/src，并把 <uvm_base>/src/uvm_base_pkg.sv 排在包之前；
  2. 事务继承 uvm_base_item，配置继承 uvm_base_cfg；
  3. driver / monitor 继承模板基类，只实现协议相关方法；
  4. env / test 继承基类，test 只需返回“主序列”和“主 sequencer”；
  5. 项目 Makefile 里 FILELIST/TOP/DEFS/PLUS 指向自己，调用 uvm_base/scripts/run_vcs.sh。

5. 通用脚本用法

# 编译 + 仿真（任何项目通用）
FILELIST=./filelist.f TOP=tb_top TEST=xxx \
DEFS="+define+DW=8" PLUS="+NUM_FRAMES=3" \
bash <uvm_base>/scripts/run_vcs.sh

# 只看波形
FILELIST=./filelist.f TOP=tb_top WAVE=waves/tb_top.fsdb bash <uvm_base>/scripts/run_verdi.sh
变量说明
FILELIST / TOP必选：文件列表与顶层模块
TEST / SEED / VERB用例名、随机种子、冗余度
UVM_VERuvm-1.2（默认）/ uvm-1.1d
DEFS追加 +define+...
PLUS追加运行时 plusarg
DUMP / WAVE波形开关与格式（fsdb / vcd / none）
COV1 = 收集代码覆盖率
OUT可执行文件与 KDB 名字（默认 simv）
VCS_CC / VCS_CXX老 VCS 指定编译器，如 VCS_CXX=g++-4.8
COMP_ONLY / RUN_ONLY只编译 / 只仿真
通用 plusarg（基类已支持）：+TMO_NS= +DRAIN_NS= +NUM_ITEMS= +PRINT_TOPO=1 +PASSIVE=1 +EXPECT_ERR=1 +REQUIRE_ERR=1

7. 作为 Git 项目使用

  • 已提供 .gitignore：忽略 simv/ csrc/ logs/ waves/ *.fsdb *.log .vcs_compat/ 等仿真产物；
  • 建议目录布局（两仓库平级）： 
    <your_repo>/
├── uvm_base/      # 通用母版（可单独打 tag，如 v1.0.0）
└── dvp_uvm/       # 项目（依赖 ../uvm_base，filelist 中为相对路径）
  • 升级 uvm_base 时，只改新项目 filelist.f 里的 ../uvm_base 路径或 Makefile 的 UVM_BASE ?=。
